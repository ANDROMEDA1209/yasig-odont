# Manual del equipo

La franja de demo identifica datos ficticios. No introducir historias reales. Fecha y hora se muestran en Ecuador; los reportes señalan expresamente las columnas que contienen UTC.

1. **Acceso:** utilizar el correo y contraseña de la cuenta. Mostrar/Ocultar cambia la visibilidad de la contraseña. Recordarme mantiene un token revocable hasta 14 días. La sesión normal expira después de 30 minutos de inactividad. El botón de salida cierra la sesión y revoca el token del navegador.
2. **Pacientes:** Nuevo paciente → completar datos → guardar. El código se genera automáticamente y el documento no puede duplicarse. Buscar por nombre, apellido, documento o código. Ver ficha permite editar y, con permiso clínico, abrir historia y odontograma.
3. **Solicitudes web:** Agenda → Solicitudes del sitio web → Revisar solicitud. Registrar al paciente si es nuevo, seleccionar paciente, profesional y servicio, revisar horario y confirmar. La solicitud web no bloquea un profesional hasta que se le asigna. Cancelar solicitud permite rechazarla sin crear un paciente.
4. **Agenda:** elegir día, semana o mes, fecha y filtros. Pulsar una cita para editar hora, fecha y estado. La duración procede del servicio. Las reservas superpuestas se rechazan en el servidor. La disponibilidad de cada profesional aparece al final; se administra en Configuración.
5. **Historia clínica:** seleccionar paciente, consultar antecedentes y evoluciones. Registrar evolución y confirmar la firma. Una entrada cerrada no tiene edición. Para corregirla, crear una entrada nueva y seleccionar el número de la anterior. Se conservan autor, fecha y antecedentes de cada firma. Adjuntos: PDF/JPG/PNG hasta 5 MB; la descarga exige permiso clínico. Imprimir historia genera una vista de impresión.
6. **Odontograma:** al seleccionar un paciente se recupera su versión vigente con piezas, superficies y observaciones. Consultar o guardar sin cambios no crea versiones. Si no existe registro, pulsar Crear primer odontograma tras completar la evaluación. Para actualizar: pieza → superficie → estado y observación → Aplicar hallazgo → Guardar actualización. Se conserva cada estado anterior y sus notas. Al abrir una pieza se selecciona su superficie con hallazgos; los procedimientos realizados se consultan junto a la pieza y en la tabla inferior. Nueva evaluación requiere confirmación y utiliza el estado vigente como punto de partida, conservando todo el historial. Aplicar un estado al diente completo reemplaza sus superficies en la edición actual. Una versión anterior es solo lectura; Volver al estado actual permite continuar la atención. Si otro usuario guardó primero, recargar y revisar antes de reintentar. La orientación es la derecha/izquierda del paciente, con numeración FDI. El módulo no realiza diagnósticos automáticos.
7. **Tratamientos:** editar precios y duración en el catálogo. Crear un plan con paciente y profesional; el primer procedimiento queda planificado. Añadir procedimientos y registrar evolución/cambiar estado cuando corresponda. Completar un procedimiento es una acción explícita. El presupuesto conserva el precio que tenía al agregarlo, aunque el catálogo cambie.
8. **Caja:** seleccionar plan y registrar un importe parcial o total. El servidor impide pagos superiores al saldo. Abrir un comprobante para imprimirlo: es interno, no factura tributaria. Una anulación exige motivo, conserva el cobro y vuelve a abrir el saldo. Antes de cancelar un procedimiento, anular los cobros que dejarían el plan sobrepagado.
9. **Inventario:** crear material con unidad y mínimo. Registrar cantidades positivas como entradas y negativas como salidas, siempre con lote y motivo. El vencimiento se establece al crear el lote. No se permite consumir un lote vencido ni generar stock negativo. Consultar el historial para reconstruir movimientos.
10. **Reportes:** seleccionar tipo y fechas inclusivas, consultar y descargar CSV o PDF. Saldos utiliza los planes creados en el período y su saldo actual. Consumo muestra entradas y salidas firmadas; cantidades negativas son consumo. CSV neutraliza celdas que podrían interpretarse como fórmulas.
11. **Usuarios y roles:** crear cuentas sin registro público. Activar/desactivar invalida sesiones. Crear un rol y configurar sus módulos. Los permisos base del administrador están protegidos. No conceder clínica a personal que no la necesite.
12. **Configuración:** completar datos públicos, WhatsApp internacional solo con dígitos, profesionales y horarios. El logotipo oficial se incorpora como archivo. En demo, restablecer exige escribir RESTABLECER DEMO y una segunda confirmación; elimina datos operativos y adjuntos, recrea los usuarios demo y cierra la sesión.

Perfiles iniciales: administrador completo; odontólogo con pacientes, agenda, clínica y tratamientos; recepción con pacientes y agenda; asistente con inventario; caja con pagos y reportes. Todos tienen dashboard. El ingreso monetario solo se muestra con permiso de pagos o reportes.
